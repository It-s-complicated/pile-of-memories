# Airspace lexicons

The board and workspace schemas are generated from `src/lib/airspace-model.ts`:

```sh
node node_modules/airspace/bin/airspace.mjs lexicons emit --lexicons src/lib/airspace-model.ts --out lexicons
```

Before deploying the OAuth storage integration, publish both schemas from the
account that controls this namespace. Set `AIRSPACE_APP_PASSWORD` securely in
the publishing environment, then run:

```sh
node node_modules/airspace/bin/airspace.mjs lexicons publish --lexicons lexicons --identity YOUR_PUBLISHING_HANDLE --authority app.pileofmemories.prototype --dry-run
node node_modules/airspace/bin/airspace.mjs lexicons publish --lexicons lexicons --identity YOUR_PUBLISHING_HANDLE --authority app.pileofmemories.prototype
```

Configure `_lexicon.prototype.pileofmemories.app` with the TXT value
`did=YOUR_PUBLISHING_DID`, as printed by the publishing command. Publication
requires control of this domain; generated JSON files alone do not publish
lexicons to the AT Protocol network. See the
[AT Protocol publication guide](https://atproto.com/guides/publishing-lexicons).

App sign-in requests identity access only. Choosing Airspace restores that
session and requests the scopes generated by `scopesFor({ spaces: { workspace } })`
when needed. Consent returns to the Airspace storage choice. Board operations
run on the server using the restored session; its DID resolves the PDS.
Private-space support and member-list read/write policies remain mandatory.
The static core build offers browser storage only because it has no OAuth server.

The publishing password is an operator credential, never an application login
or a board-storage credential. Live publication and an end-to-end test against
a spaces-enabled PDS still require the namespace owner's publishing setup.
